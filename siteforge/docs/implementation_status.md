HR & Workforce slice 3 is open: shifts, crews, attendance, corrections, and period locks. A shift has start and end times, a break, a calendar note, effective dates, and the day an overnight shift counts on. ## Implemented and verified

- Drawings have a number, title, type, discipline, responsible engineer, originator company, location, planned preparation date, priority and an optional work reference. The work reference is text. It is not a work-package link. Disciplines are Electrical, Mechanical, Civil, Instrumentation, plus any discipline an administrator adds. A drawing can use only a discipline enabled on the project.
- Manual creation and CSV/XLSX import share one validation path. An identical number, title, discipline and company is skipped. The same number with different content is reported as a conflict and is not overwritten. Import can succeed for the valid rows.
- Drawing identity is separate from revision records. A submitted, reviewed or accepted revision is not overwritten. A correction is a new revision. Returned, rejected, superseded and withdrawn revisions stay with their files, decisions and comments.
- Review uses the Phase 2 policy, inbox, tasks and notifications. The first stage is internal (`drawings.review`). A second stage, when configured, is client (`drawings.client_review`). Actions are approve, approve with comments, return, reject and comment. The preparer cannot approve or release. A returned drawing review cannot be resubmitted; the engineer adds a revision.
- Comments store the revision, page or reference, severity, owner, due date, response and closure evidence. An open blocking comment on that revision blocks release.
- Construction release is a separate command. It requires `drawings.release`, an accepted or accepted-with-comments review, an available file and no open blocking comment. Accepted with comments does not release the revision. Releasing a newer revision marks the previous released revision Superseded and notifies the responsible engineer and lead PM. No Construction table is written.
- Transmittals pin revision ids, recipients, purpose and issue date. Dispatch marks the transmittal Issued and notifies recipients. Acknowledgement is recorded per recipient and does not change the review or release state.
- Dashboard counts use each drawing once, through its latest revision. The latest released revision is shown separately, so a newer revision under review does not hide the released revision. Filters are discipline, company, owner, status bucket and planned date. Each count filters the same register. Overdue preparation, review and comment response notify the owner, then discipline heads with review authority, then the lead PM. A repeated scan does not notify again and does not approve anything.
- Wrench configuration cannot be enabled. Manual entry and import work while it is disabled. A manual external id can be stored. A later different id is kept as a conflict and does not change the drawing. `POST /api/projects/{id}/wrench/sync` returns 409. No Wrench API is called.

## Not in this phase

- Work packs and technical queries. Material take-off and procurement demand are described above.
- Correspondence, RFIs, short-lived download links, OCR, retention, legal hold and dossier packages.
- A working Wrench connector. The specification and credential label can be stored. The secret and the API contract are still required before any connector is written.
- Archive, delegation, holiday calendars, email and an outbox table. Project contacts are a directory only.
- Construction, quality, safety or planning records created from a release.
